**Context.** `kb index` was leaving a 127KB `agents/knowledge.db` in whatever directory it ran in — the stray file that prompted `.gitignore` to start ignoring `*.db` in `f12a59b`, which was treating a symptom. Probing every entry point to find the cause showed the help paths, the test suite and every `make` target were clean, and that `index` alone was at fault: `mainRun` opens the ambient database before dispatching, and `index` never queries it, having been built to work from the record files so it runs in a checkout that has never been ingested (DR-0008). `merge` was already special-cased for exactly this, with a comment calling it "a pointless, surprising side effect for a verb that never touches it."

Looking for the analogous handling of `-version` and `-license` turned up that **kb has neither**, at all. The cause is structural rather than an oversight: `parseGlobalFlags` was a hand-rolled loop over `--db`/`--json`/`--debug`, so every option had to be written out by hand along with each dash spelling, and two were simply never written. Every other Go CLI in these two workspaces — `clasm`, `scripttool`, `mdtools`, `harvey` — declares `help`, `license` and `version` through the `flag` package under a `// Standard Options` comment and answers them before doing any work.

**Decision.** `parseGlobalFlags` returns a `globalOptions` struct populated by a `flag.FlagSet`, registering `help`, `license` and `version` alongside `db`, `json` and `debug`. `flag` accepts both dash forms per declaration, so `-help` and `--help` are one option rather than two cases. A `FlagSet` rather than the package-level default, following `mdtools`, because `mainRun(args, out, errOut) int` takes its arguments explicitly and returns a code instead of calling `os.Exit`, which is what makes the whole path testable. `-h` is **not** declared: left undefined, `flag` returns `ErrHelp` for it, and `mainRun` answers that with the real help page. The three standard options are answered and returned before the debug log, before path resolution, and before `knowledge.Open`. `index` joins `merge` in the branch that never opens a database.

**Rationale.** The two problems have one shape — doing initialisation work for a request that does not need it — and one fix. Declaring the options through `flag` is the part that keeps it from recurring: a hand-rolled parser makes every option a small cost, and options that are pure overhead to write are the ones that never get written, which is precisely how a CLI ends up without `-version`. Not declaring `-h` is the smaller nicety: `flag` reserves it as a signal when undefined, so catching `ErrHelp` gets the conventional spelling without a declaration whose only purpose would be to shadow the Pandoc help text with a generated usage line.

`FmtHelp` is why the drift test is worth having. Help text carries `{app_name}`, `{version}`, `{release_date}` and `{release_hash}` placeholders that `FmtHelp` substitutes from `version.go`, which `cmt` regenerates from `codemeta.json` — so a help page, whether read through the CLI or as a generated man page, states the release it belongs to, and a page naming a different one is a stale artifact rather than a matter of opinion. The test asserts `Version` only. Asserting `ReleaseHash` would fail on every commit by design, since `make build` re-stamps it from HEAD; that same re-stamping is why a build always dirties `version.go`, the installers and all thirteen man page sources, which is normal here rather than a signal.

**Rejected alternatives.** Adding two cases to the hand-rolled loop — it fixes today and leaves the reason the gap existed in place. Declaring `-h` explicitly — it would print the FlagSet's usage over the real help. Using the package-level `flag` functions as `clasm` and `scripttool` do — they parse `os.Args` directly, which would cost `mainRun` its testability, and `mdtools` already establishes the `FlagSet` variant in-house. Reverting `.gitignore`'s `*.db` rule now that the cause is fixed — bare `kb` launches the TUI and legitimately creates a database, so a stray one is still possible; the rule stays, but its justification is now belt-and-braces rather than load-bearing. Moving `cmd/kb/helptext.go` to the repository root, where it belongs and where harvey keeps its own, so that its constants can serve TUI help as well as man pages — real, agreed, and its own change rather than a rider on this one.

**Consequences.** `go build`/`go vet`/`gofmt`/`go test` clean. Every informational path was re-probed against the built binary: `-h`, `-help`, `--help`, `help`, `help TOPIC`, `-version`, `--version`, `-license`, `--license`, `index` and `merge` all leave no database behind; bare `kb` still creates one, correctly, because the TUI needs it. `kb(1)` gains a STANDARD OPTIONS section, its GLOBAL FLAGS section is renamed GLOBAL OPTIONS, and the synopsis shows the three shapes: standard options, verb with parameters, and the `help` verb with a topic. It also now states that a global option must precede the verb, since parsing stops at the first non-option argument — which is what lets `kb -json ingest DIR --dry-run` route `--dry-run` to ingest, covered by a test. One thing worth recording for anyone editing `helptext.go`: its constants are backtick-delimited raw strings, so Markdown backticks cannot appear in the prose — an attempt to add them broke the build immediately. The man page chapters beyond 1 remain unused here; `MAN_PAGES_3` and `MAN_PAGES_7` exist in the Makefile with working build and install rules but are commented out of the `man` prerequisites, and harvey's dozen `harvey-*.7.md` topic pages are the model whenever kb grows conceptual topics such as a `kb-decision-records.7`.
