**Context.** W2 builds `ParseRecordFile`/`RenderRecordFile`, whose acceptance criterion is a byte-identical round trip over all 198 live records. Reading `decision-records-design.md` and `decision-records-plan.md` against `go.mod` before writing any code turned up two problems. First, the design states that `gopkg.in/yaml.v3` "is present in `go.mod` but currently marked `// indirect`" and that the work is merely to promote it; it was not in `go.mod` at all, so this was a new third-party dependency needing approval rather than a bookkeeping change. Second, and more consequential, the stated acceptance criterion is unreachable with plain `yaml.Marshal`: it emits `title`, `uuid` and `origin_host` bare where all 198 records quote them, and it quotes `phase` only when the value happens to resolve as a number — `"20.51"` quoted because it would otherwise be a float, `0.0.46` left bare because it would not — making the rendering value-dependent in exactly the field `DECISION_RECORD_FORMAT.md` singles out as needing quotes. A survey of all 198 records found the frontmatter otherwise strikingly regular: one key order, and a per-field quoting policy with zero counterexamples, including the rule that `trigger`/`project`/`session` render `""` when empty and bare when populated. The single real inconsistency was `decisions[]`, written as a block sequence in six CMTools records and as an inline list in the other eight that populate it — and the format's own "scalars and inline lists only" rule makes the six a conformance defect rather than a style preference.

**Decision.** The `recordFrontmatter` struct declaration is the format specification. Field order is the emitted key order; `,flow` on `supersedes`/`superseded_by`/`relates_to`/`decisions`/`tags` satisfies the inline-lists rule and normalises the six block-style records for free; and a `qstr` string type whose `MarshalYAML` returns a `yaml.Node` with `Style: yaml.DoubleQuotedStyle` pins `id`/`title`/`date`/`phase`/`initiative`/`uuid`/`origin_host` regardless of value. `qstr.UnmarshalYAML` takes the node's value verbatim, so a bare `id: 0142` still yields `"0142"` with its padding and a bare `date: 2026-08-19` never becomes a timestamp — no `time.Time` exists anywhere in the parse path. The corpus is normalised to this form rather than the renderer replaying per-file style, and because `qstr` matches what the corpus already does, 192 of the 198 records render byte-identically today; only the six CMTools records change. Closed vocabularies are **reported, not enforced**: an out-of-vocabulary `status`/`kind`/`trigger`, a scalar written without the required quoting, and an unknown frontmatter field each parse, carry a warning, and are preserved. Missing or empty required fields remain hard errors.

**Rejected.** A style-preserving renderer that replays however each file was written — it would meet the original byte-identical criterion without touching the corpus, but it makes every later writer carry provenance it has no reason to care about, and `kb index` and `kb record` both share this parser under workspace DR-0003, so a formatting accident from one authoring session would leak into two more tools. Hand-rolling the parser as well as the renderer to avoid the dependency — feasible against a closed 17-key schema, but `clasm` DR-0164's escaped quotes and CMTools' backtick-and-`$HOME` strings are exactly where a naive parser goes wrong, and `yaml.v3`'s emitter was verified to round-trip a title containing escaped quotes, a backslash and a colon. Enforcing the vocabularies as the plan's W2 text literally requires — design decision 5 says documented-not-enforced, and enforcement in a file several harnesses write turns a typo into a failed run rather than a fixable row; the two documents contradicted each other and this resolves it in decision 5's favour, matching the temperament of design decision 6's non-fatal unresolvable references. Folding normalisation into `ingest` as a write-back flag — W3's rule is that ingest never writes to record files, so it needs its own verb.

**Consequences.** `go build`/`go vet`/`gofmt`/`go test` clean. The corpus round-trip test reports "round-tripped 198 records; 6 normalized as expected" and asserts that set in both directions, so an unexpected file changing fails and so does one of the six failing to change; divergent files must still render to a fixed point, and normalisation must leave the body untouched. Two follow-ups fall out of this and are tracked in W5 rather than done here: `~/WorkLab/CMTools/decisions/`'s six records need `kb record fmt` run over them, and `DECISION_RECORD_FORMAT.md`'s example needs `uuid` and `origin_host` quoted to match both the 198 records and this renderer. A bare `id` or `date` in a hand-edited file now parses, warns, and is silently re-quoted on the next write — the warning is what makes that visible, and it is the reason the quoting check exists at all. Verified before committing to the approach rather than after: the emitter does not fold long values, with a 593-character `decisions` line and a 177-character title both staying on one line, so the format's greppable-one-line requirement holds.
