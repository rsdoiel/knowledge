**Context.** W7 is documentation and downstream. Two of its items turned out to rest on false premises, both mine, and finding that out is most of what this record is for. `~/Laboratory/CLAUDE.md` lists the `Makefile` among the files `cmt` generates and therefore must not be hand-edited — but W7 needs three new verbs added to `KB_TOPICS`, a variable nothing in `codemeta.json` could produce, and `git log` shows it was already hand-extended once when `export`/`import` were added. And the plan's "out of this repo, but blocked on it" section says the grounding query and five skills "filter `source_type`" on `('project','observation','concept')` and so miss every record — a claim I had repeated for two days, written into three memories and two knowledge-base observations, and never checked.

**Decision.** The `Makefile` is hand-maintained: regenerate `version.go`, `README.md`, `about.md` and `CITATION.cff` in this repo, never the `Makefile`. `CLAUDE.md` now says so, alongside the existing harvey exception, and a CMTools feature request for protected regions in generated files is filed in `~/WorkLab/CMTools/TODO.md`. Help coverage is enforced by three tests driven off the `verbs` map rather than any hardcoded list: every registered verb has a help topic, appears in `kb(1)`, and appears in `KB_TOPICS`. The grounding query in `WorkLab/CLAUDE.md` and `rag-query`'s three variants now order by `bm25(kb_fts)`. `kb-schema` gained the `records`/`record_relations` DDL in all three variants. Version is `0.0.4`, with `gopkg.in/yaml.v3` recorded in `softwareRequirements`.

**Rationale.** The `Makefile` is the more interesting of the two, because the failure would have been silent in two layers: `cmt` would have removed `KB_TOPICS` and `kb-topics-help`, and `MAN_PAGES_1` is a shell glob over the `.1.md` files that already exist, so `make man` would then have stopped generating verb pages and still reported success. A file whose header invites a regeneration that destroys work is worse than one with no header at all, which is what the CMTools request is about. Enforcing help coverage from the `verbs` map rather than a list is the same principle applied to this repo's own tests: the hardcoded list in `TestPrintHelp_AllVerbTopicsRecognized` is precisely what let `ingest`, `record` and `index` ship with no `kb(1)` entry and no man page.

**A wrong diagnosis, and what was actually wrong.** Nothing filters `source_type` — there is no `WHERE source_type IN (...)` in `CLAUDE.md`, in `rag-query`, or anywhere else, and records were being returned all along. The defect was `ORDER BY source_type` combined with `LIMIT 20`. `record` sorts last of the four values alphabetically, so records were the *first* rows the limit discarded, and they now dominate the corpus: `decision` matches 306 rows of which 193 are records, and **zero** were reachable in the top 20; `restore` 65 and 25 and zero; `schema` 21 and 8 and seven, which is the only reason the symptom was ever intermittent. Ordering by `bm25` — relevance, which the Go `Search` API had used all along — puts 12 records in the top 20 for `decision`. The symptom I described was real; the mechanism was not, and the fix a `source_type` filter would have needed does not exist.

**Rejected alternatives.** Regenerating the `Makefile` and re-adding `KB_TOPICS` afterwards — it works once and loses the next person, who has no way to know the file is not what its header claims. Raising the grounding query's `LIMIT` instead of fixing the ordering — it defers the same failure to a slightly larger corpus and keeps sorting on a field that has no bearing on relevance. Making observation kinds reported-not-enforced for symmetry with records — design decision 5's argument applies to a file several harnesses write, not to an API call, and harvey depends on the rejection; the asymmetry is pinned by a test instead. Updating `setup-knowledge-base` — it still creates the pre-migration `experiments` schema, which is a larger staleness than the records gap, and the honest fix is retiring it, since `knowledge.Open()` creates and migrates the whole schema on first use.

**The security pass found one real defect.** The SQL is clean — every concatenation in the new code is of a compile-time column-list constant and every value goes through a `?` parameter, including the `LIKE` prefix, which is escaped as well. But `set-status` and `supersede` did `filepath.Join(root, rec.Path)` on a path read from the database, and `Join` cleans a path without confining it: `Join("/a/b", "../../etc/x")` is `/etc/x`. Ingest cannot store an escaping path — `relativeTo` falls back to the base name — but a hand-edited database, a direct SQL insert or a merge from another machine could, and `set-status` would then rewrite an arbitrary file. Both choke points now go through `resolveWithinRoot`, which refuses a path that resolves outside the root. Worth recording how the test behaved: the first version passed *without* the fix, because the file it planted outside the root had no frontmatter and the parse error stood in for the confinement check that did not exist. Only after planting a *valid* record there did the test go red and demonstrate the write. A security test that passes for the wrong reason is worse than none, since it certifies the gap it was written to find.

**Consequences.** `make kb-topics-help` and `make man` produce 13 pages including `kb-ingest.1`, `kb-record.1` and `kb-index.1`. `go build`/`go vet`/`gofmt`/`go test` clean. Downstream: `WorkLab/CLAUDE.md`, `rag-query` (`SKILL.md` plus both compiled scripts) and `kb-schema` (same three) are updated; `review-knowledge-base` and `update-knowledge-base` needed no ordering change; `setup-knowledge-base` is deliberately untouched. The two wrong knowledge-base observations were corrected by a further observation rather than edited, and the three memories were corrected in place. Two things W7 surfaced and did not do: `kb index --check`, exiting non-zero on a stale index — nothing detects index drift today, which is how promoting DR-0004..0006 desynced it — and `kb export` covering the `records` table, which is defensible to leave, since the record files are versioned and `kb ingest` rebuilds the rows. Also noted and deliberately not acted on: `cmd/kb/helptext.go` belongs at the repository root, as it is in harvey, because its constants serve TUI help as well as man pages; relocating it is its own change.
